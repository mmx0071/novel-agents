# 卷生命周期与衔接章（短约定）

Studio 编排细则见 `studio.md`；本文件供章纲 / 正文 / 剧情验收等子 Agent 对齐，避免只记得「写下一章」。

## 卷相位（`volume_phase`）

| 相位 | 含义 | 子 Agent 注意 |
|------|------|----------------|
| `drafting_volume` | 本卷可写章 | 正常规划/写作 |
| `awaiting_sync` | 卷末待同步设定 | **不要**假定可开新主线高潮；等 Studio `sync_volume`/跳过 |
| `awaiting_next_arc` | 待下卷卷纲 | 禁止当本卷续写 |
| `awaiting_next_plot` | 待下卷第一段剧情卡 | 禁止无卡硬写 |

一张剧情卡收束 ≠ 整卷结束。勿把卷纲终止条件当成单卡收束。

## 薄卷契约（超长篇）

- 默认按 **约 20–40 章/卷** 推进；本卷约 20 章应跑 `audit_volume`，勿习惯性 `confirm_skip`
- 单卷拖到 60–100 章会使卷打包摘要抽样变稀，卷审质量下降——优先结卷/开新卷，而非无限续写同卷
- 卷 rollup 会热区保留最近若干卷，更早的卷摘要归档后仍可召回

## 剧情卡节奏

- 一卷同时只推 **一张** `in_progress` 主线卡（`scope=local`）
- 卡**不预估章数**；完结只看卡面**收束条件原文**
- 禁止一张卡复述整卷卷纲；禁止叠卡（有进行中卡或欠衔接时勿开新卡）

## 衔接章（桥接章 / `needs_bridge`）

| 点 | 约定 |
|----|------|
| 何时 | 剧情卡 `completed` 后若卡面要求衔接（`needs_bridge`），下一章先写衔接 |
| 职责 | 消化上一剧情余波与落点，钩住下一剧情卡；**不要**开全新主线高潮 |
| 章纲 | `goal`=消化余波；`key_events` 勿开新弧高潮；`cliffhanger` 导向下一卡 |
| 正文 | 开篇接住上一卡余波；章末导向下一卡进入，而非伪完成下一卡收束 |
| 验收 | 衔接章**不是**用「又推进了很多」判旧卡 pass；旧卡应已 completed |

## 与审校/发布

- 剧情验收未通过：**阻断发布**（与一致性 P0 同类）；缺口是「补收束」，不是整章作废；章后卡只给「修正本章」
- 假卷末：卷纲阶梯未走完时勿宣称本卷结束
